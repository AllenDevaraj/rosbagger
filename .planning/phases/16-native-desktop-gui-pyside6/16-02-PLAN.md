<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Query box → query() | The user's SQL string crosses into the query engine |
| desktop GUI → rosbagger_core (offline) | A user-chosen bag path + SQL handed to core; core owns all bounds |
| offline import graph → Qt | The Query panel module must stay Qt-only at top level (no core/ROS leak) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-02-SQLI | Tampering | the SQL query box | accept (inherited) | `query()` resolves + quotes identifiers via sqlglot (the single established injection boundary, Phase 3/5); the GUI forwards the string verbatim and builds no SQL |
| T-16-02-TEACH | Information disclosure | error rendering | mitigate | Catch only the Phase-7 teaching errors (UnknownTable/Column/UnresolvedType) and render `str(e)` (core-built messages); never surface a raw traceback to the user |
| T-16-02-DOS | Denial of Service | rendering a query result | accept (inherited) | `query()` already bounds the result + gates heavy blobs (QURY-07); the panel uses the eager `to_pylist()` form the TUI proved safe and re-derives no bounds |
| T-16-02-ISO | Tampering | query_panel.py import graph | mitigate | All `rosbagger_core` imports inside method bodies (verified by the no-top-level-core-import grep); the Plan 16-01 Qt-free guards continue to cover the package |
</threat_model>
