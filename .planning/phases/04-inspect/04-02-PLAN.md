Phase 3 schema API (rosbagger_core.schema, re-exported in schema/__init__.py):
  build_table_schema(msgtype: str, typestore, *, topic: str) -> TableSchema
    # raises KeyError if msgtype is None — caller MUST guard
  class TableNameResolver:
      def resolve(self, topic: str) -> str            # /image -> "image"; idempotent; collision-resolving
      @property def mapping(self) -> dict[str, str]    # recorded topic -> table name (copy)
  sanitize_table_name(topic: str) -> str               # /a/b -> a_b

  @dataclass(frozen=True, slots=True) class TableSchema:
      table_name: str       # sanitized, collision-resolved (e.g. "camera_image_raw")
      topic: str            # original topic
      msgtype: str
      columns: list[ColumnDef]
      def column_names(self, include=None) -> list[str]   # heavy blobs hidden unless in include
  @dataclass(frozen=True, slots=True) class ColumnDef:
      name: str             # dotted column name, e.g. "linear.x", or standard t/t_ns/stamp/topic
      arrow_type: object    # real pyarrow.DataType; str(arrow_type) renders e.g. "timestamp[ns]", "int64", "list<item: uint8>"
      ros_path: tuple[str, ...]
      is_heavy_blob: bool   # True for Image.data (verified: arrow_type=list<item: uint8>)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bag file → schema build | Untrusted bag topic/msgtype strings drive table-name sanitization and schema flattening |
| schema output → terminal | Table names and column names/types are rendered to the user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Denial of Service | collect_table_schemas over a hostile/huge bag | mitigate (by design) | Builds schema from the DECLARED msgtype + typestore (`build_table_schema`) and O(1) `reader.topics` metadata; it NEVER calls `reader.read()` or deserializes a message body — schema not rows. A multi-GB bag yields its schema in constant time. Enforced by the acceptance criterion that `collect_table_schemas` contains no `reader.read(`. |
| T-04-06 | Tampering / Injection | hostile topic name (e.g. `/foo; DROP TABLE`) → table name shown | mitigate | Table names go through Phase 3 `TableNameResolver`/`sanitize_table_name`, which restricts output to the `[0-9A-Za-z_]` allow-list; `tables` only prints these safe names to a terminal — no SQL is built in Phase 4 (Phase 5 owns SQL + `sqlglot` quoting). |
| T-04-07 | Information disclosure / DoS | heavy-blob column rendered into terminal | mitigate | `tables` lists the blob column's NAME and TYPE only (`data: list<item: uint8>`), annotated as lazy — it builds schema, never reads the blob bytes (no `build_arrow_table` / row materialization here). |
| T-04-08 | Crash (availability) | multi-msgtype topic → `build_table_schema(None,...)` KeyError | mitigate | `collect_table_schemas` guards `info.msgtype is None` and skips the topic (Pitfall 4), so a heterogeneous-type recording cannot crash `bagq tables`. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — `rosbags`/`rich`/`typer` are already-audited deps (04-RESEARCH.md Package Legitimacy Audit: no install step). No legitimacy checkpoint required. |
</threat_model>
