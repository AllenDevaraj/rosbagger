<objective>

Purpose: INSP-01 (list topics with msgtype + count) and INSP-02 (duration, approximate Hz, size). This is the per-topic overview half of Phase 4 Inspect. Per design decision 1 (API-first), all computation lives in the core module; the CLI only renders.

Output: `inspect.py` (new module), additive properties on `RosbagsReader` (+ matching `BagReader` ABC contract), an `info` subcommand on the existing `bagq` typer `app`, and two test files (API against fixtures + a CLI smoke test).
</objective>

RosbagsReader currently exposes ONLY these public metadata members (reader/rosbags_reader.py),
each guarded by a before-open RuntimeError:
  @property def topics(self) -> Mapping[str, object]      # reader.topics[name] -> rosbags TopicInfo
  @property def connections(self) -> Sequence[object]
Internals available to passthrough: self._reader (AnyReader | None), self._paths (list[Path]).

rosbags AnyReader (verified 0.11.2) O(1) properties to passthrough:
  reader._reader.message_count -> int          # whole bag, summed across opened bags
  reader._reader.start_time    -> int (ns)     # min across sub-readers; sys.maxsize on empty bag
  reader._reader.end_time      -> int (ns)     # max; 0 on empty bag
  reader._reader.duration      -> int (ns)     # end-start; large-NEGATIVE on empty bag
  reader._reader.typestore     -> Typestore    # set in AnyReader.open()
rosbags TopicInfo NamedTuple fields: (msgtype, msgdef, msgcount, connections)
  reader.topics[name].msgtype  -> str | None   # None when topic carries >1 msgtype
  reader.topics[name].msgcount -> int

Fixture facts (tools/make_fixtures.py, verified): 3 topics, 3 msgs each = 9 total.
  /cmd_vel -> geometry_msgs/msg/Twist  (no header)
  /imu     -> sensor_msgs/msg/Imu
  /image   -> sensor_msgs/msg/Image    (data uint8[] blob)
  timestamps 1.0s / 1.1s / 1.2s  ->  duration = 200_000_000 ns (0.2s)
  ROS1 fixture is a single .bag FILE; ROS2 sqlite/mcap fixtures are DIRECTORIES (metadata.yaml + data file).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bag file → inspect API | Untrusted external bag metadata (topic names, msgtype strings, counts, time bounds) is read off `AnyReader` and surfaced to the user |
| bag directory path → filesystem | `_path_size_bytes` walks the given bag path with `rglob`/`stat` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Denial of Service | collect_bag_info over a hostile/huge bag | mitigate (by design) | API reads ONLY O(1) `AnyReader` metadata (`message_count`/`topics`/`duration`); it NEVER calls `reader.read()` or deserializes a message body, so a multi-GB or decompression-bomb bag is inspected in constant time/memory. Enforced by the acceptance criterion that `inspect.py` contains no `reader.read(`. |
| T-04-02 | Tampering / Injection | topic & msgtype strings rendered by `bagq info` | accept | Strings are only printed to a terminal via `rich`; no SQL is built and nothing is `eval`/shell-interpolated in this phase (Phase 5 owns SQL, where `sanitize_table_name`/`sqlglot` quoting apply). `rich` does not interpret control content as markup for plain `add_row` values. |
| T-04-03 | Information disclosure | empty-bag garbage time bounds shown to user | mitigate | `message_count == 0` guard sets duration/start/end to None so no `sys.maxsize`/negative-duration artifact is surfaced (Pitfall 1). |
| T-04-04 | Tampering | bag path argument (`_path_size_bytes` rglob/stat) | accept | The path is a local file the invoking user already has OS permission to read; operations are read-only (`stat`/`rglob`) and stay within the given path. No privilege boundary is crossed. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — `rosbags`/`rich`/`typer` are already-audited Phase 1/2 deps (04-RESEARCH.md Package Legitimacy Audit: no install step). No legitimacy checkpoint required. |
</threat_model>
