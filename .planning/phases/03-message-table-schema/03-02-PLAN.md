<objective>
Build the heart of Phase 3: the ROS-type-system → Arrow-type-system translator (`types.py`) and the recursive flattening walk that turns a message type into a `TableSchema` (`flatten.py`). This covers dotted/quoted scalar columns (QURY-02), the LIST / LIST-of-STRUCT type mapping (QURY-03, type side), and the four always-present columns `t`/`t_ns`/`stamp`/`topic` (QURY-04).

It introspects via the VERIFIED `typestore.get_msgdef(msgtype).fields` `Nodetype` AST — never the dataclass `f.type` string, never runtime `isinstance` — so the schema is stable across messages (including empty arrays). Row-value extraction and the live `pyarrow.Table` build land in 03-03.

Purpose: Produce a stable, typed `TableSchema` per topic from the declared message definition, with dotted scalar columns and the standard time columns.
Output: `schema/types.py`, `schema/flatten.py` (the `build_table_schema` half), and `tests/test_schema_flatten.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bag content -> column name | Message field names (and custom-msg type names) become dotted SQL column identifiers in Phase 5 |
| message definition -> recursion | A malformed/deeply-nested or self-referential custom .msg definition drives the recursive walk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering | dotted column names from `_walk_fields` | mitigate | Column names are stored on `ColumnDef.name` as plain strings, never concatenated into SQL here; SQL-time quoting via `sqlglot.exp.to_identifier(quoted=True)` is wired in 03-03 (Pattern 6). This plan only produces quotable names. |
| T-03-04 | Denial of Service | recursive `_walk_fields` over `get_msgdef().fields` | mitigate | Recurse ONLY on `Nodetype.NAME` and STOP at `ARRAY`/`SEQUENCE` (so a heavy/large array subtree never explodes into columns — Pitfall 4); carry an optional `seen` frozenset to break self-referential cycles (Pitfall 5). Standard ROS types nest only a few levels. |
| T-03-05 | Denial of Service | very large fixed arrays / future heavy blobs in the type map | accept | The schema layer only records the column TYPE here; it materializes no values (row build is 03-03, where the lazy-blob `include` seam is the DoS guard). RESEARCH Assumptions A1-A4 (rare base types) are LOW risk and no fixture exercises them. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No installs — `pyarrow`/`rosbags` already locked + audited Phase 1 (RESEARCH "Package Legitimacy Audit", all Approved). `from rosbags.interfaces import Nodetype` uses the verified import path; the deprecated `rosbags.typesys.base`/`typesys.types` paths are explicitly avoided. |
</threat_model>
