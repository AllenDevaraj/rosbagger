Output: the row-extract + Table-build half of `schema/flatten.py`, the real `TableSchema.arrow_schema`, `schema/identifiers.py`, `schema/__init__.py`, and `tests/test_schema_arrow.py`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bag content -> SQL identifier | Topic/field-derived table & column names render to SQL identifiers (quoted here via sqlglot for Phase 5) |
| bag content -> in-memory Arrow | Field VALUES (incl. multi-MB byte blobs) flow into pyarrow arrays; values are inert data, never executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Tampering | `quote_ident` (sqlglot) | mitigate | All identifiers render via `sqlglot.exp.to_identifier(name, quoted=True)`, which escapes embedded quotes (`weird"name` -> `"weird""name"`) and neutralizes `x"; DROP TABLE y;--` into a single quoted identifier — VERIFIED. No f-string hand-quoting anywhere (RESEARCH anti-pattern). This is the phase's primary SQL-identifier-injection defense for Phase 5. |
| T-03-07 | Denial of Service | `build_arrow_table` heavy-blob materialization | mitigate | The QURY-07 lazy-blob `include` seam IS the DoS guard: `SEQUENCE`-of-byte columns (`Image.data`/`PointCloud2.data`) are omitted from the schema AND skipped during the Table build unless explicitly named in `include` (driven by Phase 5's parsed SQL), so a query that never references `data` never loads multi-MB blobs per row. |
| T-03-08 | Tampering | field VALUES into `pa.array` | accept | Field values (strings, byte blobs) are carried as inert Arrow data and never interpolated into SQL; only identifiers are. Building arrays with explicit `type=` (Pitfall 1) also prevents schema-confusion from a hostile empty/heterogeneous stream. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No installs — `pyarrow`/`sqlglot`/`rosbags` already locked + audited Phase 1 (RESEARCH "Package Legitimacy Audit", all Approved, no `[ASSUMED]`/`[SUS]`/`[SLOP]`). `duckdb` stays OUT of shipped `schema/` code (a future Phase-5/test concern). |
</threat_model>
