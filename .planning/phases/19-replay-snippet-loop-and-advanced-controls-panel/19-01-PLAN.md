<objective>
Add an in/out **region loop** `[t_in, t_out]` to the pure `Replayer` — DISTINCT from the existing whole-bag `loop` (which rewinds to index 0): when a region is set and run() is playing, playback wraps from the item past `t_out` back to the first item at/after `t_in`, so a user can loop a snippet of the bag on repeat. The region is stored as ABSOLUTE `t_ns` bounds so it shares the `position_fraction` basis the panel (19-03) maps fractions through.

Mechanism (RESEARCH §2a, the decided design — two new lock-guarded setters + a single run() wrap branch placed AFTER the bound guards): `self._loop_in_ns` / `self._loop_out_ns` (both `None` = no region), `set_loop_region(in_ns, out_ns)` (normalize `in<=out`, lock-guarded + wake) and `clear_loop_region()` (lock-guarded + wake), a `loop_region` read property returning `(in,out)|None`, and a region-wrap branch in run()'s advance block that takes precedence over the whole-bag `_loop` when a region is set. Reuses the Phase-18 lock + wake contract verbatim — no new concurrency primitives.

Purpose: This is the pure-scheduler tier of the v0.5 snippet-loop feature (CONTEXT locked decision: region loop markable BOTH ways). 19-02 (Scrubber handles) and 19-03 (panel sub-panel) wire on top; this plan proves SC1 (region wrap, clean clear) and SC4 (purity + Phase-13/18 invariants preserved) at the pure tier.
Output: a `scheduler.py` with the region loop (stdlib-only; `threading` already present — NO ROS, NO Qt) and deterministic region-loop unit tests in `tests/test_replay_unit.py`.
</objective>
