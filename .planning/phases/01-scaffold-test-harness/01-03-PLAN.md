VERIFIED rosbags 0.11.2 write API (the central landmine — the published docs are STALE; transcribe from 01-RESEARCH.md Code Examples, do NOT copy the rosbags website):
- ROS2: `from rosbags.rosbag2 import Writer, StoragePlugin` then `Writer(path, version=9, storage_plugin=StoragePlugin.SQLITE3)` or `...MCAP`. `version=` is a REQUIRED keyword arg; `StoragePlugin` is a MODULE-LEVEL export of `rosbags.rosbag2` (NOT `Writer.StoragePlugin`). `add_connection(topic, msgtype, typestore=ts)` — `typestore` is keyword-only. Serialize with `ts.serialize_cdr(msg, msgtype)`.
- ROS1: `from rosbags.rosbag1 import Writer` (a DIFFERENT Writer; single-file `.bag`; no version/storage_plugin args). Serialize with `ts.serialize_ros1(msg, msgtype)`.
- Typestores: `from rosbags.typesys import Stores, get_typestore`; `get_typestore(Stores.ROS2_HUMBLE)` for ROS2, `get_typestore(Stores.ROS1_NOETIC)` for ROS1.
- Re-open: `from rosbags.highlevel import AnyReader`; `with AnyReader([path]) as r: msgs = list(r.messages())` yields `(Connection, t_ns:int, raw:bytes)`.
</interfaces>

<notes>
Verified, runnable sketches for every piece of this plan are in 01-RESEARCH.md "Code Examples" 1-4 and 8 (all executed live with rosbags 0.11.2 and PYTHONPATH="" / no ROS). The executor MUST transcribe those signatures rather than the stale published docs.

THREE landmines (01-RESEARCH.md Pitfalls 1-3) the executor MUST avoid:
1. Pitfall 1 — `Writer('/path')` without `version=` raises `TypeError`. Always pass `version=9` for ROS2.
2. Pitfall 2 — `Writer.StoragePlugin.MCAP` raises `AttributeError`. Import `StoragePlugin` from `rosbags.rosbag2`.
3. Pitfall 3 — a shared header helper breaks: ROS1 `std_msgs/msg/Header` requires a `seq` field that ROS2 dropped. Build headers PER-FORMAT (ROS1: `Header(seq=0, stamp=..., frame_id=...)`; ROS2: `Header(stamp=..., frame_id=...)`). Do NOT share one message-builder helper across ROS1 and ROS2.

Open-question resolutions (from the planning directives / 01-RESEARCH.md recommendations):
- O-2: generate fixtures into a pytest `tmp_path` (no committed binary bags — they are version-coupled to rosbags and `.gitignore` already excludes them), AND expose the generator as a runnable module for manual on-disk use.
- O-4: INCLUDE a heavy-blob `sensor_msgs/msg/Image` (tiny, e.g. 2x2 RGB → `data` is `uint8[]`) in the fixtures now — same API, saves a Phase 3 fixture change (QURY-07 lazy blob).

Forward-looking content the fixtures MUST carry (01-RESEARCH.md phase_requirements + Code Examples 8), so Phases 2-3 need no fixture change:
- `/cmd_vel` `geometry_msgs/msg/Twist`: nested scalars (`linear.x`), NO header → later tests `stamp` IS NULL (QURY-04) and dotted-column flattening (QURY-02).
- `/imu` `sensor_msgs/msg/Imu`: has `header.stamp` (QURY-04 stamp extraction) and `orientation_covariance` float64[9] (QURY-03 LIST column).
- `/image` `sensor_msgs/msg/Image`: `data` uint8[] heavy blob (QURY-07 lazy materialization).

Keep timestamps explicit/deterministic (e.g. `t_ns = 1_000_000_000 + i*100_000_000`) so fixtures are reproducible. `numpy` is available transitively via `rosbags` for array fields (e.g. `np.zeros(9)`).

Generator placement (01-RESEARCH.md "Where should the fixture generator live?"): keep it in `tools/` — importable by tests and runnable as `uv run python -m tools.make_fixtures`. Do NOT put it inside `rosbagger_core`'s shipped namespace (it is a dev artifact, not a product feature). It is NOT added to either package's runtime dependencies.

File-ownership note for parallel execution: this plan owns ONLY `tools/` and `tests/test_fixtures.py`. ## Trust Boundaries

Phase 1 is dev infrastructure. This plan writes test artifacts; it has no auth, no network service, no untrusted input, no persistence beyond throwaway tmp bags, and no cryptography.

| Boundary | Description |
|----------|-------------|
| generator → filesystem | the generator writes bag files into a caller-supplied directory (tests use throwaway tmp dirs) |
| generator import graph → host ROS | the generator must stay ROS-free even though `rosbags` writes ROS bag formats |

Surface area is intentionally narrow; nothing here is rated `high`.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

(The dedicated offline guard in plan 01-02 covers the shipped packages; the generator's ROS-freedom is asserted by its import list and exercised in ROS-free CI.) |
| T-01-FIX-WRITE | Tampering / DoS | filesystem writes | accept | The generator writes only to a caller-supplied directory (tests pass throwaway `tmp_path`); the manual `__main__` default targets a `.gitignore`d `fixtures/` dir. No path traversal surface — paths are constructed by the caller, not from external input. |
