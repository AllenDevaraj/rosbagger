Output: A new `output/` subpackage (`render.py`, `export.py`, stdlib-only `__init__`), the `bagq query` command, and three test files (render coercion, export read-back, CLI smoke).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user CLI args → `COPY result TO '<path>'` | The user-supplied output path is interpolated into a DuckDB SQL string — the ONE place this phase builds SQL |
| user-chosen output path → filesystem | `-o`/output path selects where files are written (the user picked it on their own CLI) |
| bag data → output files/stdout | Untrusted bag-derived strings (topic names, string fields) already materialized in Arrow (Phase 5) flow into CSV/Parquet/stdout |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `write_table` COPY path literal (export.py) | mitigate | Escape `'`→`''` in the path before interpolating into `COPY result TO '<path>'` (RESEARCH Security Domain). The only SQL this phase constructs; format chosen from a closed `{csv,parquet}` map, never from user text |
| T-06-02 | Tampering | output path → filesystem (`-o`, `/dev/stdout`) | accept | Local single-user CLI; the user chose the path and can only overwrite their own files. No traversal control needed beyond the quote-escape above; documented disposition |
| T-06-03 | Information disclosure | bag strings → CSV/stdout | accept | rich and DuckDB `COPY` both quote/escape correctly (RESEARCH "Don't Hand-Roll": never hand-build CSV). Bag data is the user's own; no new exposure. Disposition: accept |
| T-06-SC | Tampering | pip/uv installs | accept | This plan ADDS no package (matplotlib is added in 06-02). duckdb/pyarrow/rich/typer are pre-existing locked deps (RESEARCH Package Legitimacy Audit: all Approved). No `[ASSUMED]`/`[SUS]` package → no install checkpoint needed |
