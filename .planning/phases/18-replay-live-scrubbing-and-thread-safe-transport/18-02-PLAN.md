# Phase 18 Plan 02: Desktop Live-Scrub Wiring (Thin Face)

**Phase:** 18 — Replay live scrubbing and thread-safe transport
**Plan:** 02 of 2
**Subsystem:** rosbagger-desktop (Replay panel)
**Requirements:** REP-02 -> ROADMAP Phase 18 SC2, SC3, SC4
**Depends on:** 18-01 (thread-safe `Replayer`). Wave 2.

---

## Objective

Turn the Replay tab into a real playback surface on 18-01's now-thread-safe `Replayer`: the scrubber **playhead tracks live during playback**, and the user can **drag the scrubber (and change rate / toggle loop) while it plays** — no more "Pause before seeking." A backward drag honestly reports a forward-resume (jump + forward replay, not a rewind). The panel stays a **thin face**: only drives the library + updates widgets; no analysis/ROS logic, no inline color, offline/Qt-free import graph intact.

---

## Acceptance Criteria

(AC# trace to ROADMAP Phase 18 Success Criteria.)

1. **AC1 (->SC2) live playhead.** While a drive worker runs, the scrubber playhead advances in real time (a UI-thread `QTimer` polls `position_fraction`); it stops updating when the drive ends. Headless pytest-qt test.
2. **AC2 (->SC2/SC3) live seek.** `scrubber.seeked(fraction)` while playing performs `replayer.seek(...)` with the right offset and produces NO "Pause before seeking" rejection. Headless test (spy on `replayer.seek`).
3. **AC3 (->SC3) backward honesty.** A backward drag sets a status communicating the jump + forward resume (e.g. "Seeking to N% — resuming forward."), never claiming reverse playback.
4. **AC4 (->SC2) controls stay live.** Rate input + loop checkbox remain ENABLED during playback and apply mid-play (no disable in `_start_drive`; `_apply_rate`/`_apply_loop` no longer reject while running).
5. **AC5 (->SC4) invariants.** Panel module top stays PySide6+stdlib+local only; `tests/test_offline_guard.py` green; thin face preserved; no inline color (shared `set_status`); `QTimer` lifecycle bounded (start on drive start, stop on drive finish AND `closeEvent`).
