<objective>
Implement `RosbagsReader(BagReader)` — the concrete v1 reader, a thin adapter over `rosbags.highlevel.AnyReader`. It opens ROS1 `.bag` / ROS2 sqlite3 / ROS2 MCAP bags uniformly (READ-01/02/03), iterates `AnyReader.messages()` lazily to yield `Message` records with correctly derived `stamp` (READ-04), exposes `topics`/`connections` metadata without full deserialization (for Phase 4 Inspect), and accepts a list of bag paths to read as one logical dataset (READ-05).

Purpose: This is the phase's actual contribution — ~90% adapter glue. `AnyReader` already does format detection, definition registration, deserialization, and multi-bag merge; this reader adapts its `(connection, t_ns, rawdata)` tuples into the project's `Message` shape and derives the four fields, especially the uniform `stamp` extraction that works for both ROS1 and ROS2.

Output: `reader/rosbags_reader.py` (the `RosbagsReader` class + `_stamp_ns` helper) and an extended `reader/__init__.py` that re-exports `RosbagsReader`.
</objective>

    - `__init__(self, paths: str | Path | Iterable[str | Path], *, default_typestore=None)`: normalize a single str/Path OR an iterable of them into `self._paths: list[Path]` by coercing every element with `Path(...)` (Pitfall 5 — `AnyReader` calls `.exists()`/`.suffix`, so a bare `str` raises `AttributeError`). Accept a lone path (wrap in a one-element list) and an iterable of paths. Store `self._default_typestore = default_typestore` and initialize `self._reader: AnyReader | None = None`. Do NOT open in `__init__` (open is explicit / via the context manager from the base class).
    - `open(self) -> None`: construct `AnyReader(self._paths, default_typestore=self._default_typestore)` and call `.open()`; assign to `self._reader`. (Construction may raise `AnyReaderError`/`FileNotFoundError`; let it propagate per the design — re-wrapping is deferred, see below.)
    - `close(self) -> None`: if `self._reader is not None`, call `self._reader.close()` then set `self._reader = None`. Make it idempotent (safe to call when already closed / never opened).
    - `read(self) -> Iterator[Message]`: this MUST be a generator (use `yield`), never build a list. Guard with a clear error if not opened (e.g. raise `RuntimeError("RosbagsReader.read() called before open()")` when `self._reader is None`). Iterate `for connection, t_ns, rawdata in self._reader.messages():`, then `msg = self._reader.deserialize(rawdata, connection.msgtype)`, and `yield Message(topic=connection.topic, t=t_ns, t_ns=t_ns, stamp=_stamp_ns(msg), msgtype=connection.msgtype, msg=msg)`. Do NOT pass any sort/merge of your own — `AnyReader.messages()` already heapq-merges time-ordered (Pattern 3 / anti-pattern: re-sorting).
    - `topics` property -> `Mapping[str, object]`: return `self._reader.topics` (guard: raise the same not-opened RuntimeError if `self._reader is None`). This is metadata-only, no deserialization (feeds Phase 4 Inspect).
    - `connections` property -> `Sequence[object]`: return `self._reader.connections` (same not-opened guard).

    Inherit `__enter__`/`__exit__` from `BagReader` — do NOT redefine them.

    Do NOT implement: any file sniffing / magic-byte format detection (AnyReader does it), any k-way merge or timestamp re-sort (AnyReader does it), any eager `list(...)` of messages, message→table flattening or DuckDB column typing (that is Phase 3). Error re-wrapping into a project `BagReaderError` is the researcher's open question #2 and is OPTIONAL — for v1, let `AnyReaderError`/`FileNotFoundError` propagate unchanged (Phase 7 will handle teaching-error UX). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bag file -> RosbagsReader | **This is where bag files become untrusted input.** Attacker-controllable ROS1/ROS2/MCAP binaries (malformed CDR, forged/oversized headers, compressed payloads) are parsed via `rosbags.AnyReader`. The reader is a local CLI library: no network, no auth, no sessions, no persistence. |
| caller-supplied paths -> Path/AnyReader | User-chosen local filesystem paths handed to `AnyReader` (which calls `.exists()`/`.suffix`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-D1 | Denial of Service | `RosbagsReader.read()` parsing a malformed/corrupt bag (bad CDR, forged msgdef) | mitigate | Delegate ALL wire parsing to battle-tested `rosbags`; never hand-roll a parser, never `eval`/`exec` bag content. Let `AnyReaderError` propagate (fail closed) rather than crashing on partial data. (02-RESEARCH.md Security Domain V5; Pitfall 4.) |
| T-02-02-D2 | Denial of Service | decompression bomb (lz4/zstd) or huge bag exhausting memory | mitigate | `read()` is a lazy generator deserializing one message at a time — never `list()`-materializes the bag in production. Heavy byte blobs (`Image.data`/`PointCloud2.data`) are deferred to Phase 3/QURY-07. Decompression itself is `rosbags`' responsibility; we do not buffer whole bags. (02-RESEARCH.md Security Domain; anti-pattern "Eagerly listing all messages".) |
| T-02-02-S | Spoofing | forged / unknown embedded message definition (`msgdef`) | accept | `AnyReader` registers embedded defs and dispatches deserialization; we do not blindly trust defs beyond what `rosbags` validates, and we do not execute them. A bag with no resolvable defs raises `AnyReaderError` ("no type definitions") — surfaced, not silently mis-parsed. Custom-msg registration UX is Phase 7/CLI-04. Low risk for an offline read-only tool. (Pitfall 4.) |
| T-02-02-T | Tampering | path handling of caller-supplied bag paths | accept | Inputs are the invoking user's own local paths in a single-user CLI; no privilege boundary is crossed. Coerce to `Path`; `AnyReader` checks `.exists()`. No path-traversal elevation beyond the user's own FS. (02-RESEARCH.md Security Domain — Tampering row.) |
| T-02-02-SC | Tampering | npm/pip/cargo installs | accept | This plan installs NO new package. `rosbags` was locked in Phase 1 and rated `[OK]` by slopcheck (02-RESEARCH.md Package Legitimacy Audit); transitive deps carry no ROS module. No new supply-chain surface. |

> ASVS L1: the only applicable category is V5 Input Validation (untrusted binary parsing). Posture = "delegate untrusted-binary parsing to vetted `rosbags`, stay lazy, propagate errors cleanly." Nothing rated `high`: no network/auth/persistence, single-user local tool, parser is a hardened third-party library.
</threat_model>
