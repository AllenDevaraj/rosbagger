<objective>
Deliver the three errors-that-teach (CLI-02/03/04) on top of 07-01's `teaching_errors` mechanism, keeping the API-first split: `rosbagger_core` raises TYPED, framework-free `ValueError` subclasses CARRYING the data (suggestions, columns-by-table, registration guidance); the `bagq` CLI only presents them. Add the CLI-04 def-less-bag fixture so the registration-guidance path is testable.

Purpose: An unknown table/column/custom-msg should TEACH the next move, not dump a traceback or a bare "not found". CLI-02 enriches the existing `UnknownTableError` with `difflib` did-you-mean; CLI-03 adds `UnknownColumnError` by catching `duckdb.BinderException` in `query()` and attaching the referenced tables' columns; CLI-04 adds `UnresolvedTypeError` by wrapping the specific `rosbags.AnyReaderError` "no type definitions" at the reader boundary (so info/tables/query all benefit).
Output: A new stdlib-only `rosbagger_core/errors.py`; enriched `backend/query.py` (did-you-mean on the table error + BinderException→UnknownColumnError); a narrowed catch in `reader/rosbags_reader.py.open()`; a widened `teaching_errors` catch set in `cli.py`; `write_def_less_bag` in `tools/make_fixtures.py`; and a new offline-guard regression for `errors.py`.
</objective>
