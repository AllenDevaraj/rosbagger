<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell argv → bagq CLI | user-supplied SQL string + bag paths + `-o` output path cross here (intended interface of a local single-user tool) |
| bag file → rosbagger_core reader | bag-derived names (table/column/type names) cross here; later echoed back in error messages |
| result table → output/export | the `-o` path is interpolated into the DuckDB `COPY ... TO '<path>'` literal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `COPY ... TO '<path>'` literal in `output/export.py` (`_copy_to`, reused by new `write_csv_to_string`) | mitigate | PRESERVE the existing `'`→`''` single-quote escape in `_copy_to`; the new buffered writer reuses `_copy_to` (does NOT build its own SQL), so the one escape boundary is unchanged. Format chosen from the closed `{csv,parquet}` map, never from user text. |
| T-07-02 | Information Disclosure | clean error messages echo bag-derived table/column/type names back to the terminal | accept | Local single-user CLI — the user already owns the filesystem and the bag. Echoing the bag's own names IS the feature (CLI-02/03/04). Messages are printed as DATA via `typer.secho`/`typer.echo` (never re-interpreted/`eval`'d). No cross-user disclosure. |
| T-07-03 | Denial of Service | `teaching_errors` wrapper / buffered CSV temp file | accept | The wrapper catches a bounded, known error set (no recursion/loop). `write_csv_to_string` writes to a single `mkstemp` file and unlinks it in a `finally` (no leak); CSV size is the result size the user already requested. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | NO new packages this phase (07-RESEARCH Package Legitimacy Audit: none added — `difflib`/`os`/`tempfile` are stdlib; `typer`/`rich`/`duckdb` already locked). No install task → no slopcheck checkpoint needed. |
