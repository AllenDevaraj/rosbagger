<objective>
Complete EVNT-01: wire the reserved `events` table into the query orchestrator (D-14/D-15) and surface the thin `bagq events add` / `bagq events list` verbs (D-02). The sidecar I/O (`sidecar_path`/`add_event`/`list_events`) landed in Plan 11-03; this plan makes `events` queryable. When the SQL references `events`, `query()` subtracts it from the topic-resolution set (so it never raises `UnknownTableError`), derives the sidecar next to the single bag (`reader.paths[0]`), and registers it as the `events` relation — after which a standard SQL `BETWEEN` interval join works natively against topic tables on `t_ns` (D-15, no special operator). When no sidecar exists, an empty-schema `events` table is registered so joins yield zero rows (Open Q3 LOCKED). This plan also adds the offline-import guard for `rosbagger_core.events` (the module Plan 11-03 created).

Purpose: deliver the two remaining success criteria — SC2 surfaced at the CLI (`bagq events add` then `bagq events list` round-trips) and SC3 ("the `events` table is queryable and JOINable against data by time"), proven by an interval-join test across all three formats.

Output: the events hook in `backend/query.py`, the `bagq events` sub-app (add/list) in `bagq/cli.py`, the interval-join + reserved-name + absent-sidecar tests in `tests/test_backend_query.py`, the CLI round-trip test in `tests/test_cli_events.py`, an `add_event`→`bagq events list` integration touch in `tests/test_events.py` (optional), and the events offline-guard pair in `tests/test_offline_guard.py`. No new dependencies.
