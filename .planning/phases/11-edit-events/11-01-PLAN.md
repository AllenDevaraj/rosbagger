<objective>
Build the edit core: a single streaming `AnyReader` raw-stream `(connection, t_ns, rawdata)` → filter/transform → `rosbags` Writer pipeline (`rosbagger_core/edit/` — D-03) that produces a NEW output bag (never in-place — D-05) from the raw-copy edit operations — trim (D-06), drop/keep (D-07), downsample (D-08), and implicit multi-bag merge (D-09) — composed in a single read→write pass, with the output Writer chosen by output format (D-10). This plan covers ONLY the same-format raw-copy half of D-04 (no cross-format byte conversion; that is Plan 11-02). The pipeline copies `rawdata` losslessly with no typestore round-trip when input and output serialization match.

Purpose: deliver the bag-editing engine that the success criterion SC1 ("trim/drop/merge/downsample produce valid bags that re-open via AnyReader") names — proven by round-trip tests that re-open AND deserialize every kept message (Pitfall 1/2), across all three formats. This is the foundation Plan 11-02 (convert) extends with the cross-format converter factory and the `bagq edit`/`convert` CLI verbs.

Output: a new `rosbagger_core/edit/` subpackage (`__init__.py`, `operations.py`, `pipeline.py`), a new `tests/test_edit.py` round-trip suite, and an extension to `tests/test_offline_guard.py` for the edit module. No CLI changes (Plan 11-02 owns the verbs). No new dependencies.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| input bag(s) → edit pipeline (read) | Untrusted bag content crosses here. The pipeline reads raw `(connection, t_ns, rawdata)` and topic names from `AnyReader`; these become Writer `add_connection` arguments (data), never SQL or shell. |
| edit pipeline → output bag path (write) | A user-supplied filesystem path. The Writer takes it directly; no SQL/shell interpolation. The one constraint is D-05: the output must not be (overwrite) an input path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | output path overwriting an input bag (data loss) | mitigate | D-05 forbids in-place edit; `edit_bag` raises a clear `ValueError` if the resolved `dst` equals any input path (RESEARCH Security: "Overwriting the input bag"). |
| T-11-02 | Denial of Service / poor UX | bag with unresolvable custom msgtype crashes the read with a traceback | mitigate | Re-raise the Phase 7 `UnresolvedTypeError` teaching error on the read boundary when AnyReader reports "no type definitions" (copy `RosbagsReader.open()`'s pattern); mixed-format `AnyReaderError` propagates clearly (Pitfall 6). |
| T-11-03 | Injection | hostile topic name from an untrusted bag escaping into SQL/identifier | accept | The edit pipeline never puts topic names into SQL — they pass to `Writer.add_connection` as plain strings (RESEARCH Security: no injection surface). No mitigation code needed. |
| T-11-04 | Tampering / DoS | malformed/oversized input bag | accept | Local single-user offline CLI; the user supplies their own bags (consistent with the project's local-CLI threat model, T-06-02). Streaming (no list-materialization) bounds memory. |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages (RESEARCH § Package Legitimacy Audit: N/A — no install surface). No install task → no `[ASSUMED]`/`[SUS]` legitimacy checkpoint applies. |

The output path traversal disposition is *accept* (local single-user CLI), consistent with T-06-02.
