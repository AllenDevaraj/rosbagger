<objective>
Surface the Phase-20 RViz-fidelity opt-ins in the desktop Replay panel: add "Publish /clock" + "Re-publish static on seek" checkboxes to the EXISTING Phase-19 Advanced sub-panel, thread them into `build_publish_sink` at transport-build time, and re-prime the static topics after a seek when enabled. Both default OFF — the panel's existing behavior is unchanged unless explicitly enabled.

Mechanism (RESEARCH §2c, the decided design): two `QCheckBox`es ("Publish /clock" + "Re-publish static on seek") added to the existing `_advanced_body` QGroupBox (the Phase-19 collapsible sub-panel), both `setChecked(False)`. They set panel flags that `_ensure_transport` threads into `build_publish_sink(self._node, publish_clock=self._clock_checkbox.isChecked(), static_topics=(frozenset({"/tf_static"}) if self._static_seek_checkbox.isChecked() else frozenset()))`. When "Re-publish static on seek" is on, `_on_seeked` (AFTER the existing `replayer.seek(...)`) calls the 20-02 republish helper to push the tracked static items back through the sink so a fresh scene re-primes. No inline color (status via `set_status`); every `rosbagger_replay` import stays inside method bodies; `build_publish_sink` is only CALLED with the new kwargs — never re-implemented.

Purpose: This proves SC3 (both behaviors opt-in via the side sub-panel; defaults unchanged — the UI half) and SC4 (offline/Qt-free guard green; `import rosbagger_replay` stays ROS-free; full headless suite ≥80%). The panel stays a THIN face — Phase-18 live scrubbing (playhead poll, drag-while-playing seek) and the Phase-19 region loop are untouched. The library mechanism comes from 20-02 (`build_publish_sink` opt-ins + `republish_static`); this plan is the thin Qt face that drives them.
Output: an updated `replay_panel.py` + new headless pytest-qt tests in `tests/test_desktop.py`.
</objective>
