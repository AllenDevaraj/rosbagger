<objective>
Create the PURE, ROS-free decision tier for Phase-20 RViz fidelity: a `StaticTracker` that records the latest `ReplayItem` per configured "static" topic (default `/tf_static`) and returns that re-publish set, plus a `clock_stamp_ns(t_ns)` time-split helper for the `/clock` message build. Both live in a NEW stdlib-only `rosbagger_replay/fidelity.py` and are re-exported from the package front door WITHOUT pulling ROS.

Mechanism (RESEARCH §2a, the decided design): `class StaticTracker` constructed with a static-topic set (default `frozenset({"/tf_static"})`); `record(item)` stores `item` as the latest for its topic IFF `item.topic` is in the static set (a cheap dict write); `republish_items()` returns the currently-tracked latest items (one per static topic — the set to re-publish after a seek so a fresh subscriber re-primes); `clear()` resets. `clock_stamp_ns(t_ns) -> (sec, nanosec)` is pure arithmetic via `divmod(t_ns, 1_000_000_000)` (the actual `rosgraph_msgs/msg/Clock` build is the LIVE boundary in 20-02 — only the time math is pure + tested here). Both operate on the rosbags-free `ReplayItem` value record, so the module imports only stdlib.

Purpose: This is the pure tier of the Phase-12/13 two-tier strategy — the decision logic is ROS-free and unit-testable, satisfying SC2 via the explicitly-allowed "unit test over the publish sink's static-tracking" route (CI route) and SC4 (offline/Qt-free guard green; `import rosbagger_replay` stays ROS-free). 20-02 (live publish wiring) and 20-03 (desktop toggles) wire on top of these contracts.
Output: a new `fidelity.py` (stdlib-only), a `__init__.py` re-export, offline unit tests, and an extended offline guard.
</objective>
