# 260608-2g6 SUMMARY — Code-review hardening: 3 defensive fixes

**Source:** xhigh `/code-review` of `7d86a31..HEAD` (Phase 23 RViz/overlay/Rerun work). Of 8
findings, 3 were worth fixing; the rest are by-design (global `_TRACKED_RVIZ_PIDS` mirrors the
accepted Rerun-viewer pattern and is single-window-safe; hardcoded port 9876 is a niche
multi-instance limit needing rerun-sdk investigation; `_prefer_gpu` re-stat is negligible).

**Shipped (commit `135b2c3`):**

1. **`replay_panel.py` `_on_rerun_opened` — CONFIRMED regression.** 23-01 moved the viewer spawn
   off-thread; the post-spawn `build_rerun_sink(rec, t0_ns=...)` runs in this UI-thread callback,
   so a raise there never reached `_on_rerun_open_failed` (which only catches the worker's spawn
   failure) — it propagated to the Qt event loop, leaving the button CHECKED and a viewer running
   with no mirror. Fix: record `self._rerun_rec = rec` BEFORE building the sink (so `_close_rerun`
   can close the spawned viewer on failure), wrap the build in try/except → on failure: error
   status + `setChecked(False)` (→ `_toggle_rerun(False)` → `_close_rerun()`).

2. **`replay_panel.py` `_launch_rviz` — CONFIRMED temp-file leak.** Moved
   `self._rviz_cfg_path = fh.name` to BEFORE `fh.write(cfg)` so a write failure (disk full /
   EACCES) leaves the `delete=False` temp `.rviz` path recorded for `_close_rviz()` to unlink
   instead of orphaning it; the except handler now calls `_close_rviz()` directly rather than
   relying solely on `setChecked(False)`'s toggled signal.

3. **`main_window.py` `closeEvent` — PLAUSIBLE.** Wrapped `self._overlay.close()` in
   `contextlib.suppress(Exception)` so an overlay-close raise can't skip the live-panel teardown
   loop that closes RViz/Rerun (the 260607-5xf fix) — matches that loop's existing guarding.
