# Quick 260608-2g6 — Code-review hardening: 3 defensive fixes

Source: xhigh `/code-review` of `7d86a31..HEAD` (Phase 23 work). Three findings worth
fixing; the rest are by-design (global PID set mirrors the accepted Rerun pattern;
hardcoded port is a niche multi-instance limit; `_prefer_gpu` re-stat is negligible).

## Task 1 — FIX 1: guard `_on_rerun_opened` (CONFIRMED regression)

**File:** `panels/replay_panel.py` (`_on_rerun_opened`, ~line 588).

**Problem:** 23-01 moved the viewer spawn off-thread. The post-spawn
`build_rerun_sink(rec, t0_ns=...)` now runs in this UI-thread callback with NO try/except.
`_on_rerun_open_failed` only catches the *worker's* spawn failure. If `build_rerun_sink`
raises, the exception hits the Qt event loop, the button stays CHECKED, `_rerun_sink`
stays `None`, and the viewer runs with no mirror (silent no-op). The pre-23-01 synchronous
`_open_rerun` wrapped this in try/except → this is a regression.

**Fix:** Record `self._rerun_rec = rec` BEFORE building the sink (so `_close_rerun` can close
the already-spawned viewer on failure), wrap the `build_rerun_sink` call in try/except. On
failure: error status + `setChecked(False)` (→ `_toggle_rerun(False)` → `_close_rerun()`,
matching the sibling `_on_rerun_open_failed` path) and return.

**Verify/done:** `test_replay_rerun_open_failed_sink_unchecks_and_closes_viewer` — patch
`build_rerun_sink` to raise; assert button unchecked, `_rerun_sink is None`, the viewer-close
teardown fired (spy `close_viewer`), status is error-styled. Existing
`test_replay_rerun_open_anchors_t0_off_thread` still green (success path unchanged).

## Task 2 — FIX 2: temp-file leak + direct cleanup in `_launch_rviz` (CONFIRMED)

**File:** `panels/replay_panel.py` (`_launch_rviz`, ~line 764).

**Problem:** Inside the `NamedTemporaryFile(delete=False)` block, `self._rviz_cfg_path = fh.name`
is set AFTER `fh.write(cfg)`. If the write raises (disk full / EACCES), the path is never
recorded, so `_close_rviz()` skips `os.unlink` → orphaned `.rviz` temp file. Also the except
handler relies solely on `setChecked(False)`'s toggled signal to drive cleanup.

**Fix:** Move `self._rviz_cfg_path = fh.name` to BEFORE `fh.write(cfg)`. In the except handler,
call `self._close_rviz()` directly (removes the temp cfg + kills any spawned proc) before
`setChecked(False)`.

**Verify/done:** `test_rviz_launch_write_failure_cleans_temp_file` — patch the file write to
raise; assert no orphaned temp file remains, button unchecked, error status. Existing
`test_rviz_open_builds_config_and_launches` still green.

## Task 3 — FIX 3: guard overlay close in `MainWindow.closeEvent` (PLAUSIBLE)

**File:** `main_window.py` (`closeEvent`, ~line 388).

**Problem:** The panel-teardown loop is wrapped in `contextlib.suppress(Exception)` but the
preceding `self._overlay.close()` is NOT — an overlay-close raise would skip the live-panel
teardown that closes RViz/Rerun (the whole point of the 260607-5xf fix).

**Fix:** Wrap `self._overlay.close()` in `contextlib.suppress(Exception)`; keep
`self._overlay = None`.

**Verify/done:** `test_window_close_survives_overlay_close_failure` — force `_overlay.close`
to raise; assert the live panels are still torn down (`_close_rviz`/`_close_rerun` fire) and
`_overlay` is cleared. Existing `test_window_close_tears_down_live_panels` still green.
