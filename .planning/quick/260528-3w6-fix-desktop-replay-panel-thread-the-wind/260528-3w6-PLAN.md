<objective>
Fix a real-bag replay bug: pressing **Play** on a typestore-less ROS 2 sqlite3 bag
(the format real `rosbag2` records — no embedded message definitions) raises
`AnyReaderError: Bag contains no type definitions. Instantiate AnyReader with a
default_typestore argument.`

Root cause (confirmed + reproduced): the desktop **replay panel** calls
`load_items(bag)` with NO typestore at two sites — `_ensure_transport`
(`replay_panel.py:258`) and `_load_markers` (`replay_panel.py:470`). The OFFLINE
reader path already passes the ROS-2-Humble typestore (`main_window.py:264`,
"Pitfall 5"), which is why inspect/query/tf work on the same bag but replay does
not. `rosbagger_replay.load_items` ALREADY accepts `default_typestore` — the
desktop face simply was not passing it.

Fix (desktop-only, mirrors the working offline path):
1. `main_window.py` — build the Humble typestore once, expose it as a public,
   cached `default_typestore` property; `_open_reader` uses that single source.
2. `replay_panel.py` — read `self.window().default_typestore` and pass it into
   both `load_items(...)` calls (the same `getattr(self.window(), ...)` channel
   the panel already uses for `reader` / `ros_available`).

Why it slipped through: replay tests are ROS-gated (skipped in headless CI) and
the `rosbags`-WRITTEN sqlite3 fixture self-describes, so this path was never
exercised against a def-less bag.

Output: a desktop-only fix + a STANDARD-type def-less sqlite3 fixture
(`write_ros2_sqlite_bag_defless`) + two headless pytest-qt regression tests.
</objective>
