# Quick Task 260614-37t — Summary

## Outcome
A single topic-name resolution chokepoint now backs `bagq edit`. The headline fix: `bagq edit
big.bag --keep cmd_vel -o out.bag` (forgot the leading `/`) no longer silently writes an empty
bag and reports success — it normalizes `cmd_vel` to `/cmd_vel` and writes the real result; a
genuine typo (`cmdvel`) raises a teaching `UnknownTopicError` with a did-you-mean and writes
nothing. Full offline suite **652 passed, 6 skipped**.

## What changed (`9fe0aff`)
- **`UnknownTopicError`** (errors.py) — topic sibling of `UnknownTableError`; difflib
  did-you-mean over available topics (also tries the slash-normalized form), stdlib-only.
- **`rosbagger_core/topics.py`** (new) — `resolve_topics(requested, available)` normalizes a
  missing leading `/`, returns canonical names in request order, raises `UnknownTopicError` on
  a miss. `normalize_topic()` helper. The one place every topic surface can route through.
- **`edit_bag`** — resolves `keep`/`drop`/`downsample` against `{c.topic for c in
  reader.connections}` (after open, before write) via `dataclasses.replace`, so the predicates
  match canonical names. `UnknownTopicError` added to bagq `teaching_errors`.

  keep/downsample typos raise `UnknownTopicError` with `/cmd_vel` suggestion.
