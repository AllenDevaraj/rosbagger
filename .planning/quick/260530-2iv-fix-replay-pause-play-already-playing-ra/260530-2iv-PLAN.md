# Quick Task 260530-2iv: Fix desktop Replay pause→play "Already playing" race

## Problem

User report: "if i pause and press play again it says already playing, that functionality
doesn't work." Reproduced deterministically (offline, fake replayer): pause then quickly press
Play → status "Already playing — pause before issuing a new control." and the playhead never
resumes.

**Root cause.** `ReplayPanel._play` (and `_step`) reject with "Already playing" whenever
`self._drive_running()` is True (`self._drive_thread is not None and isRunning()`). But the
Replayer's `run()` RETURNS on pause (proven: a threaded scheduler test shows `run()` returns,
state PAUSED), and the worker emits `finished` → `_on_drive_finished` clears `self._drive_thread`
ASYNCHRONOUSLY (queued to the UI thread). There is a window between the pause and that clear where
the thread still `isRunning()` while the Replayer is already **PAUSED**. A normal pause-then-play
clicks inside that window, so the guard wrongly rejects a *resume* as a *double-play*. The guard
conflates "a worker thread is tearing down" with "genuinely playing." Same race affects `_step`.

## Tasks

1. **replay_panel.py — state-aware guard + deferred resume.**
   - Add `self._pending_action: str | None = None` in `__init__` (next to the drive refs).
   - `_play`: when `_drive_running()`, only reject if the Replayer state IS `State.PLAYING`
     (genuine double-play). Otherwise (a post-pause worker is finishing) set
     `self._pending_action = "play"` and return — do NOT reject.
   - `_step`: same shape — reject only when state is `State.PLAYING`; else
     `self._pending_action = "step"` and return.
   - `_on_drive_finished`: after clearing the thread/worker refs, if a `_pending_action` is set,
     clear it and replay it (`self._play()` / `self._step()`) — now `_drive_running()` is False so
     it takes the clean path and resumes from the held cursor. `State` import stays lazy (the
     module top stays ROS-free).

2. **tests/test_desktop.py — regression (offline, fake replayer).**
   - `test_replay_pause_then_immediate_play_resumes`: a fake replayer whose `run()` blocks until
     `pause()`; click Play, Pause, then IMMEDIATELY Play (no waitUntil) → assert the status is NOT
     "already playing", and after the worker finishes the drive resumes (`_drive_running()` True).
