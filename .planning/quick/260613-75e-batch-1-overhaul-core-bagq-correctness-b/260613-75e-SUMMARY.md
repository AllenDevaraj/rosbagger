# Quick Task 260613-75e — Summary

## Outcome

First batch of the whole-codebase review overhaul: **9 CONFIRMED correctness bugs** in
`rosbagger-core` and `bagq`, each fixed with a regression test and committed atomically.
These are the self-contained query/TF/events bugs — no GUI threading, no shared-infra
refactor (those are later batches). Full offline suite: **623 passed, 6 skipped**; offline
guard **22 passed** (the 3 new error classes stay stdlib-only).

## Fixes (one atomic commit each)

| ID | Commit | Fix |
|----|--------|-----|
| newA1 | `366681f` | `has_star()` matched `COUNT(*)` and any tree-wide `Star`, so `SELECT COUNT(*) FROM image` materialized every heavy `data` blob just to count rows. Now only a projection star (bare `*` / qualified `t.*` directly in a `SELECT`) counts. |
| newA4 | `b99e9df` | `query()` built a `TableSchema` for **every** topic up front, so one unbuildable topic crashed unrelated queries. Replaced with a memoized `_schema_for(table)` built only for referenced tables. |
| newA5 | `62329f1` | Table→topic resolution was case-sensitive; `SELECT … FROM imu` on a `/Imu` bag raised `UnknownTableError` though DuckDB folds case. Added a folded fallback + dedupe. |
| newA6 | `02cfa58` | `bagq query … -o out.txt` validated the extension only after running the full query, raising a bare `ValueError` that escaped `teaching_errors` (traceback). Now preflighted to a clean `typer.BadParameter`. |
| newA7 | `5f8dc6b` | A `/tf` carrying a non-`TFMessage` type made `msg.transforms` raise a raw `AttributeError` mid-stream. Added an O(1) msgtype guard → new `NonTfMessageError` (teaching). |
| newA8 | `db3fdd0` | `collect_tf_report` read `start_time`/`end_time` past only an `isinstance(int)` guard, so an empty bag's `2**63-1`/`0` sentinels leaked (`bagq tf --format json` emitted `9223372036854775807`). Now coerces bounds to `None` when `message_count == 0`. |
| newA2 | `474996c` | `events add` used `int(start*1e9)` (truncates 1 ns short → the interval join misses the marked message). Now `round()` — the WR-06 fix already in `EditOps.trim_window_ns`. |
| newE22 | `e815a51` | A topic recorded with >1 msgtype (msgtype `None`, common across merged bags) was skipped, so a query against it failed with `UnknownTableError` listing only OTHER tables ("data missing"). Now raises a truthful new `MixedTypeTopicError`. |
| newE23 | `42c2a93` | The reserved `events` table loaded only `paths[0]`'s sidecar but joined it against the merged multi-bag stream, silently dropping other bags' events. Now raises a new `MultiBagEventsError` with >1 bag. |

## New error classes (stdlib-only, in `rosbagger_core.errors`)
`NonTfMessageError`, `MixedTypeTopicError`, `MultiBagEventsError` — each wired into bagq's
`teaching_errors` so the CLI prints a clean line, never a traceback.

## New test fixtures (`tools/make_fixtures.py`)
`write_capitalized_topic_bag` (newA5), `write_wrong_type_tf_bag` (newA7),
`write_empty_tf_bag` (newA8), `write_mixed_type_topic_bags` (newE22).
