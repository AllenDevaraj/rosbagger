# Quick Task 260530-c3p — Close the Rerun viewer when the desktop process exits

## Problem (user report)

> "i want rerun to close as well in any case our main terminal which runs the gui crashes or if
> i close it with ctrl c"

The spawned Rerun viewer **outlives the GUI**. `open_viewer()` calls `rec.spawn()`, whose default
`detach_process=True` `setsid()`s the viewer into its **own session/process group**, so it
survives the GUI closing, a terminal `Ctrl-C` (`SIGINT`), or the terminal closing (`SIGHUP`).

## Fix

Keep the blessed `rec.spawn()` launch (the mirror works) but make the viewer's lifetime track the
desktop process. In `packages/rosbagger-rerun/src/rosbagger_rerun/session.py`:

* **`rec.spawn(detach_process=False)`** — the viewer becomes a **direct child in our process
  group/session**, so:
  - a terminal **`Ctrl-C` (`SIGINT`)** and **terminal-close (`SIGHUP`)** are delivered to the
    viewer **directly** (process-group signal) → it dies with the GUI — for free; and
  - being our child, we can **kill it explicitly** on window-close.
* **Track the spawned viewer PID** via a `/proc` child-diff around the spawn (robust, name-free).
* **`close_viewer()`** — `SIGTERM` (+ non-blocking reap) every tracked viewer; idempotent (no-op
  in save mode / when already gone). Registered **once via `atexit`** (normal-exit backstop).

In `panels/replay_panel.py`: `_close_rerun()` (called on toggle-off AND in `closeEvent`) now calls
`rosbagger_rerun.close_viewer()` after the flush, so window-close kills the viewer immediately.

`open_viewer()` keeps returning `rec` (signature unchanged → save-mode tests + the live test's
monkeypatch keep working). The offline-import invariant holds (no module-top `rerun`; `os`/`signal`
/`atexit` are stdlib, imported lazily to match the file).

### Coverage

| close path | mechanism |
|---|---|
| Window close (X) / normal app exit | `_close_rerun`/`closeEvent` + `atexit` → `close_viewer()` kills it |
| `Ctrl-C` in the terminal (`SIGINT`) | process-group signal reaches the non-detached viewer directly |
| Terminal closes/crashes (`SIGHUP`) | process-group signal reaches the viewer directly |
| GUI hard-segfaults with terminal still open | NOT covered (no PDEATHSIG without owning the fork) — but the bag-end segfault is fixed in 260530-w4k; noted as a known gap |

## Test (no real viewer — would pop a window on the user's box)

`tests/test_rerun_unit.py`:
- `test_child_pids_finds_spawned_child`: `Popen` a dummy `sleep`; assert its pid is in `_child_pids()`.
- `test_close_viewer_terminates_tracked_process`: `Popen` a dummy long-lived child, add its pid to
  the registry, `close_viewer()`, assert the process is dead + the registry cleared.
- `test_open_viewer_spawns_non_detached_and_tracks`: monkeypatch `rerun.RecordingStream` to a fake
  recording `spawn` kwargs + `_child_pids` to yield a synthetic new pid; assert `open_viewer()`
  passes `detach_process=False` and tracks the new pid (save mode stays untouched).

`tests/test_desktop.py`:
- extend `test_replay_rerun_close_drops_sink_and_flushes` to assert `_close_rerun` calls
  `rosbagger_rerun.close_viewer()`.
