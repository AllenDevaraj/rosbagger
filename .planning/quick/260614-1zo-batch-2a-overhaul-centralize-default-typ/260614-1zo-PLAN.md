# Quick Task 260614-1zo — Plan

Batch 2 (shared infrastructure), part **a**: the typestore decision. Today the GUIs each
hard-code `_ros2_humble_typestore()` while **bagq passes nothing**, so the flagship CLI
raises `UnresolvedTypeError` on a *real* rosbag2 `.db3` (which embeds no message defs) even
though ROS2_HUMBLE would resolve its standard types. The fix centralizes the decision in the
reader layer so no face decides — and is verified to PRESERVE the CLI-04 teaching error for
*custom*-type def-less bags.

Empirically confirmed (rosbags 0.11.x): a standard def-less bag opened with ROS2_HUMBLE opens
and every msgtype resolves via `typestore.get_msgdef`; a custom-type def-less bag opens too
but `get_msgdef('my_pkg/msg/Widget')` raises `KeyError`. So the reader must **fall back then
verify coverage**.

## Tasks

### T1a — `resolve_default_typestore()` (new `rosbagger_core/typestore.py`)
- **action:** Read `$ROS_DISTRO`, map to a rosbags `Stores` member (`ROS2_<DISTRO>`, e.g.
  humble/iron/jazzy/kilted), fall back to `Stores.ROS2_HUMBLE` when unset/unknown; return
  `get_typestore(store)`. Lazy `rosbags` import (core discipline).
- **verify:** unit test — unset → ROS2_HUMBLE store; `ROS_DISTRO=jazzy` → ROS2_JAZZY; bogus → ROS2_HUMBLE.

### T1b/newE19 — `RosbagsReader.open()` auto-fallback + verify + no fd leak
- **action:** When no explicit `default_typestore` was given: open with the bag's embedded
  defs; on the `"no type definitions"` `AnyReaderError`, (1) force-close the partially-opened
  sub-readers (rosbags leaves them open when it raises post-loop — the **newE19** leak), (2)
  retry with `resolve_default_typestore()`, (3) verify every connection's msgtype resolves in
  that typestore — if any does not, close the reader and raise `UnresolvedTypeError`
  (CLI-04 teaching preserved for custom types). The explicit-typestore path is unchanged.
- **verify:** see T1c.

### T1c — tests
- **standard def-less bag** (`write_ros2_sqlite_bag_defless`): `bagq info`/`query`/`tables`
  now exit 0 and read rows (the T1 win) — and `RosbagsReader(bag)` (no typestore) opens.
- **custom def-less bag** (`write_def_less_bag`): still raises `UnresolvedTypeError` at the
  reader, and `bagq` still prints registration guidance (existing CLI-04 tests stay green).
- **fd leak**: repeated failed opens of the custom bag do not accumulate file descriptors
  (Linux `/proc/self/fd` count stable); a failed open leaves `_reader is None` and `close()` is safe.
- Full offline suite green; offline guard green.
