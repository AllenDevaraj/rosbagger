# Quick Task 260609-2ry — Plan

## Goal

Give the self-contained desktop cockpit **two simple launch paths**, both
documented:

1. **`rosbagger`** — one word, from *any* terminal, after a single install.
2. **`ros2 launch rosbagger_ros desktop.launch.py`** — already works; just make
   the docs show it plainly alongside method 1.

The current friction: launching needs a long in-repo command (activate venv / `uv
run …`). The only console script is the long `rosbagger-desktop`, and it is only
on `PATH` inside an activated venv.

## Constraints (from CLAUDE.md + project invariants)

- The 7 pip packages stay pure / offline-importable. The `rosbagger` alias points
  at the **existing** `rosbagger_desktop.cli:main` (argparse-first, builds Qt only
  after parse) — no new import-time cost, no ROS pulled.
- One-transaction sibling rule still holds (install.sh already encodes it).
- **No churn to the launch file internals** — `desktop.launch.py` keeps calling
  `rosbagger-desktop` (the explicit long name). Both names resolve to the same
  entry point after install.

## Tasks

### Task 1 — Add the `rosbagger` console-script alias
- **File:** `packages/rosbagger-desktop/pyproject.toml`
- **Action:** Under `[project.scripts]`, add `rosbagger = "rosbagger_desktop.cli:main"`
  alongside the existing `rosbagger-desktop` (keep both). Comment that it is the
  short, friendly brand command (same entry point).
- **Verify:** `uv lock` is a no-op or commits cleanly; `uv sync --locked` passes;
  build the wheel and confirm BOTH `rosbagger` and `rosbagger-desktop` appear as
  entry points.
- **Done:** Both commands present in the built distribution metadata.

### Task 2 — Add `--user` global-install mode to install.sh
- **File:** `install.sh`
- **Action:** Add a `--user` flag. When set, skip the venv entirely and install
  the one-transaction spec list with `pip install --user`, so the commands land in
  `~/.local/bin` and work from any terminal. Update `usage()` and the completion
  message (PATH hint via `site.getuserbase()`; no "activate" line; show
  `rosbagger` when `--desktop`; keep the sourced-ROS hint for live). Add `rosbagger`
  to the venv-mode completion hint too.
- **Verify:** `bash -n install.sh`; running `./install.sh --desktop --user`
  succeeds and reports the right commands (this doubles as Task 4).
- **Done:** `./install.sh --desktop --user` installs globally; `--help` lists `--user`.

### Task 3 — Document the two launch methods (simple)
- **Files:** `README.md`, `ros/rosbagger_ros/README.md`,
  `packages/rosbagger-desktop/README.md`, `INSTALL.md`
- **Action:** README: replace the "ROS 2 (optional)" section with an "Open the
  desktop GUI" section showing both methods plainly; note `--user` in the install
  flag list. ros README: add the `./install.sh --desktop --user` one-liner + note
  the command is `rosbagger`. desktop README + INSTALL: note the `rosbagger` alias
  and `--user`.
- **Verify:** Manual read; commands match the implemented flags.
- **Done:** Both methods discoverable from the root README in <30s.
