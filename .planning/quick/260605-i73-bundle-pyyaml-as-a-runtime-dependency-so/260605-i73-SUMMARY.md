# Quick Task 260605-i73 — Summary

## What changed

`uv run rosbagger-desktop ~/Desktop/rosbag` (and the standalone `rosbagger-record`
/ `rosbagger-replay` CLIs) now run **live** record/replay without the
`--with pyyaml` launch flag.

- `packages/rosbagger-record/pyproject.toml`: added `pyyaml>=6,<7` to `[project]
  dependencies` (deps reflowed to a multi-line list) + a comment documenting the
  ROS-companion rationale.
- `packages/rosbagger-replay/pyproject.toml`: same.
- `uv.lock`: re-locked — `pyyaml==6.0.3` now resolved and pinned as a dep of both
  packages.

## Root cause

Our own source never `import yaml` (the only `yaml` hits in `src/` are docstrings:
`metadata.yaml`, a `yaml-cpp` error string). The `ModuleNotFoundError: No module
named 'yaml'` was raised by the **environment-provided ROS packages** (`rclpy` /
`rosbag2_py` / `rosidl_runtime_py`) that the live lanes lazy-import — those
`import yaml` at runtime, but PyYAML lives on PyPI and wasn't in the uv venv.

## Why PyYAML is declared when rclpy is not (D-03)

D-03 keeps rclpy/rosbag2_py/rosidl out of `[project]` deps because they have **no
PyPI wheels** (uv would try to fetch nonexistent packages). PyYAML is the
opposite — a tiny, pure, ubiquitous **PyPI** package. It's the one ROS-runtime
*companion* we can and should declare. It installs anywhere (CI, no ROS), so the
offline-portability invariant holds, and it does NOT make `import rosbagger_record`
pull anything ROS (verified below).

## Placement

In the two live lanes (`rosbagger-record`, `rosbagger-replay`) — the packages that
need yaml at runtime. `rosbagger-desktop` depends on both, so the bare
`uv run rosbagger-desktop` gets PyYAML transitively; the standalone live CLIs are
fixed too. Hard dep (not an `[live]`-style extra) because the user needs the
**bare** command to always work.
