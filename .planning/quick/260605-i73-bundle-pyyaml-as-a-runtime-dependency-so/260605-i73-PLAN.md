# Quick Task 260605-i73 — Plan

Bundle PyYAML as a real dependency so `uv run rosbagger-desktop ~/Desktop/rosbag`
works for live record/replay **without** the `--with pyyaml` launch flag.

## Problem

Live record/replay under a bare `uv run` crashes with `ModuleNotFoundError: No
module named 'yaml'`. The workaround was `uv run --with pyyaml rosbagger-desktop`.

**Root cause:** our own source never `import yaml` (verified — the only "yaml"
hits in `src/` are docstrings: `metadata.yaml`, a `yaml-cpp` error string). The
import is raised by the **environment-provided ROS packages** (`rclpy` /
`rosidl_runtime_py` / `rosbag2_py`) that the live lanes lazy-import. Those ROS
packages `import yaml` (PyYAML) at runtime, but PyYAML lives on PyPI and is NOT
part of the ROS distro's view inside the uv venv → the bare venv has no `yaml`.

Confirmed before-state: `PYTHONPATH="" uv run --no-sync python -c "import yaml"`
→ `ModuleNotFoundError`. PyYAML absent from `uv.lock`.

## Why PyYAML may be declared (when rclpy may not — D-03)

D-03 keeps `rclpy`/`rosbag2_py`/`rosidl_runtime_py` OUT of `[project]` deps
because they have **no PyPI wheels** — `uv` would try to fetch nonexistent
packages. PyYAML is the opposite: a tiny, pure, ubiquitous **PyPI** package. It
is the one ROS-runtime *companion* we both **can** and **should** declare. It
installs anywhere (CI included, no ROS), so the offline-portability invariant
holds; it does not make `import rosbagger_record` import anything ROS.

## Placement

The packages that need yaml *at runtime* are the two live lanes:
- `rosbagger-record` (live: rclpy + rosbag2_py)
- `rosbagger-replay` (live: rclpy + rosidl_runtime_py)

`rosbagger-desktop` depends on both, so declaring it there makes the bare
`uv run rosbagger-desktop` resolve PyYAML transitively — AND fixes the standalone
`uv run rosbagger-record` / `uv run rosbagger-replay` CLIs too. Pin `pyyaml>=6,<7`
to match the repo's bounded-range convention.

NOT an `[live]`-style extra: the user needs the **bare** command to always work,
so it must be a hard dep, not an opt-in extra.

## Tasks

1. **Declare PyYAML in the live lanes.** Add `pyyaml>=6,<7` to `[project]
   dependencies` of `packages/rosbagger-record/pyproject.toml` and
   `packages/rosbagger-replay/pyproject.toml`, each with a comment explaining the
   ROS-companion rationale (why this PyPI dep is declared when rclpy is not).
   `uv lock` + `uv sync` to record it in `uv.lock` and install it.
