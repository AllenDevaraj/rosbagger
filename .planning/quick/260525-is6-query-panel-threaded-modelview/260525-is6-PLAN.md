## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user SQL string → query() | user-supplied SQL crosses into core; the panel forwards it verbatim and never builds/parses it (thin-face). Validation/teaching errors are core's. |
| worker thread → UI thread | query() result + exceptions cross the thread boundary via Qt signals; only UI-thread slots touch widgets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-is6-01 | Information Disclosure | _on_query_failed status text | mitigate | worker emits str(exc) for known teaching errors and "Query failed: <exc>" otherwise — never a traceback to the UI (preserves the Phase-7 teaching-error contract). |
| T-is6-02 | Denial of Service | re-entrant Run while a query runs | mitigate | _run_query refuses re-entry with a teaching status when `_query_thread.isRunning()`; the reader/query is not driven twice. |
| T-is6-03 | Tampering | live QThread teardown on panel close | mitigate | closeEvent calls stop_thread(self._query_thread); on_finished nulls the ref (CR-01) before deleteLater — no use-after-free on the destroyed C++ QThread. |
| T-is6-SC | Tampering | npm/pip/cargo installs | accept | no new dependencies installed; reuses existing PySide6 + workers.py only. |
