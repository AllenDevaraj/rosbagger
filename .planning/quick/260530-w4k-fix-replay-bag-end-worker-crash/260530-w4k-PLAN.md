# Quick Task 260530-w4k — Fix replay bag-end worker-thread crash (SIGSEGV/SIGBUS)

## Problem (user report)

Playing a bag to the end in the desktop Replay tab **crashes the whole GUI process** when
the bag finishes. Runtime log showed:

```
QObject: shared QObject was deleted directly. The program is malformed and may crash.
ERROR re_grpc_server: Error while receiving messages: h2 protocol error
```

The GUI (`uv run --with pyyaml rosbagger-desktop ~/Desktop/rosbag`) closed; the Rerun viewer
was open at the time (the `h2` error is the viewer losing its gRPC link as the GUI dies — a
SYMPTOM, not the cause).

## Root cause (reproduced offline, no ROS)

At end-of-track the drive worker's `run()` returns → `worker.finished` → `_on_drive_finished`
runs on the **UI thread** and does `self._drive_worker = None`.

`self._drive_worker` is a `BlockingWorker` — a **parentless** `QObject` (it must be parentless
to be `moveToThread`'d). shiboken therefore hands its lifetime to **Python**, so dropping that
last ref **deletes the C++ object from the UI thread**. But at that instant the worker thread's
event loop is still alive (`worker.finished` fired, but the `thread.quit` teardown is queued),
so the UI-thread deletion **races `worker.deleteLater()` on the worker thread** → a cross-thread
use-after-free / double-free.

Reproduction (`/tmp/repro3.py`, faithful `QApplication.exec()` loop, real `Replayer` over
fake `.t_ns` items, one bag-end per process):

| variant | single bag-end | replay-again ×8 |
|---|---|---|
| current (`base`) | **26/60 crashed** (~43%) | **30/30 crashed** |
| don't clear worker ref (`keepref`) | 1/60 | 5/30 |
| **join thread before clearing (`join`)** | **0/80** | **0/40** |

So the eager worker-ref clear is the dominant trigger, but a residual cross-thread race remains
unless the worker thread is **provably dead** before the ref is dropped. Independent of the Rerun
mirror (reproduces with and without it).

## Fix

In `panels/replay_panel.py`:

* `_on_drive_finished`: capture the thread, clear the thread ref (the `_drive_running` probe needs
  it; the thread is parent-owned so clearing its Python ref doesn't delete it), then
  **`stop_thread(thread)` (quit+wait — the worker has already finished so the join is immediate)
  to JOIN the worker thread before `self._drive_worker = None`.** Now nothing references the
  worker when Python deletes it.
* `_on_install_finished`: same parentless-worker pattern → apply the same join.

`stop_thread` already exists (used in `closeEvent`) and is `RuntimeError`-guarded, so this reuses
the proven helper.

## Test (deterministic, no segfault risk in CI)

`tests/test_desktop.py::test_replay_drive_to_done_joins_thread_before_clearing_worker`: a fake
replayer whose `run()` sets `State.DONE` and returns; drive it through the REAL worker/thread;
spy on `replay_panel.stop_thread` to assert the join is invoked with the drive thread during
`_on_drive_finished`; assert refs cleared + the terminal "Done — published N" status.
